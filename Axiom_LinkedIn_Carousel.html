The ORM Trap

The Problem

Heavy ORMs map relational tables to mutable object graphs — causing N+1 query explosions, dirty-checking overhead, and total loss of control over generated SQL.

The Fix

Relational data treated as raw streams and flat immutable maps — persistence mapped directly to data structures, no object virtualization layer.

Solved by axiom-spec and axiom-warp-jdbc and axiom-warp-reactive — direct-to-PostgreSQL parameter binding, zero reflection.

The Null Reference Trap

The Problem

Unchecked null as a default missing-value indicator leads to scattered defensive checks and production-crashing NullPointerExceptions.

The Fix

Absence becomes an explicit, typed data construct — algebraic types and sentinel structures instead of an implicit, uninitialized trap.

Solved by axiom-sovereign and axiom-language — explicit Result and sum types at every boundary.

The Annotation & DI Container Magic

The Problem

Runtime classpath scanning and annotation-driven wiring hide object lifecycles, slow startup, and produce wiring failures only discoverable at runtime.

The Fix

Explicit, manual composition — every dependency passed as a plain parameter, fully visible, with instant startup.

Solved by default — the zero-reflection, zero-scanning core all other modules build on.

The Custom Parser Void

The Problem

Reflection-based JSON parsers (Jackson, Gson) blindly slurp payloads into mutable object graphs, throwing cryptic runtime exceptions on schema drift.

The Fix

Hand-crafted parsers inspect raw byte streams directly, validating and transforming input into immutable maps and vectors — no reflection.

Solved by axiom-spec — explicit schema contracts validated at the perimeter, not inferred at runtime.

The Java Collections Desert

The Problem

Default reliance on HashMap/ArrayList means suboptimal memory layout, synchronization bottlenecks, and no true structural sharing under concurrency.

The Fix

Persistent, immutable structures — Hash Array Mapped Tries and Vector Bitmapped Tries — for safe, thread-free, cache-friendly state.

Solved by axiom — HAMT / VBT core persistent data structures.

The Exception-Driven Control Flow

The Problem

Using exceptions for expected outcomes like "UserNotFound" costs stack-trace generation overhead and hides control flow inside try/catch jumps.

The Fix

Expected outcomes return explicit Result containers and sum types — exceptions reserved strictly for unrecoverable faults.

Solved by axiom — Result-pattern return types throughout.

The Problem

Constant upgrades to build plugins, annotation processors, and codegen tools that break compatibility on every minor release.

The Fix

Zero-dependency foundations on raw JDK primitives (Loom, Amber) and standard language features that don't break underneath you.
